# 无限画布本机后台重启设计

## 目标

在无限画布空白区域的右键菜单底部增加“重启后台”操作，用于只重启当前 Infinite Canvas 后台进程（端口 3000）。操作仅允许服务器本机执行，不重启 ComfyUI、RunningHub 或其他外部服务。

## 用户体验

1. 用户在画布空白处点击鼠标右键。
2. 菜单底部显示分隔线和“重启后台”。
3. 该菜单项只在页面通过 `localhost`、`127.0.0.1` 或 IPv6 回环地址访问时显示。
4. 点击后显示确认提示，明确说明：
   - 当前生成任务可能被中断；
   - 局域网用户会短暂断开；
   - 只重启 Infinite Canvas 后台。
5. 用户确认后，菜单关闭，页面显示“后台正在重启，请稍候”状态。
6. 前端等待旧实例退出并检测新实例上线，成功后自动刷新当前页面。
7. 45 秒内未恢复时停止等待，显示错误和手动刷新提示，画布数据不被前端主动清空。

## 前端设计

- 在现有 `#createMenu` 底部增加独立的重启区域，使用分隔线与节点创建操作区分。
- 菜单项使用 `rotate-cw` 图标，中文文案为“重启后台”，英文文案为 “Restart backend”。
- 前端只依据页面主机名决定是否渲染该菜单项，用于减少误操作；这不是安全边界。
- 点击后使用确认对话框阻止误触。
- 请求重启接口后，前端记录接口返回的旧实例 ID。
- 前端每 800 毫秒请求一次轻量状态接口，只有检测到实例 ID 变化才认为重启成功，避免旧进程尚未退出时过早刷新。
- 等待期间防止重复提交，并向用户显示当前状态。
- 自动刷新使用普通页面刷新；静态资源继续沿用现有版本/缓存策略。

## 后端设计

### 状态接口

新增轻量状态接口，返回：

- `ok`
- 当前进程启动时生成的随机 `instance_id`
- 当前应用版本

`instance_id` 不包含 PID，避免暴露不必要的系统信息。

### 重启接口

新增只接受 `POST` 的重启接口：

- 检查 `request.client.host` 是否为回环地址；
- 非本机请求返回 403；
- 使用进程内锁防止同时安排多次重启；
- 返回成功响应后延迟执行重启，保证 HTTP 响应能够送达前端；
- 返回旧实例的 `instance_id`，供前端判断新实例是否真正上线。

### 重启机制

- 使用当前正在运行的 Python 解释器和当前项目目录启动无窗口辅助进程。
- 辅助进程等待短暂延迟，终止旧后台进程并等待端口释放，再以相同解释器运行 `main.py`。
- 新后台以脱离当前终端的方式启动，不调用会自动打开网页的 `启动服务.bat`，避免多开浏览器窗口。
- 重启过程写入独立日志，便于启动失败时排查。
- Windows 后台进程使用隐藏窗口；其他系统使用新的会话启动。

## 安全边界

- 前端隐藏菜单只用于体验，后端回环地址校验才是强制安全控制。
- 局域网客户端即使手工调用接口也会收到 403。
- 接口不接受目标 PID、命令、脚本路径或端口等用户输入，避免命令注入和任意进程控制。
- 重启固定指向当前项目的 `main.py` 和当前 Python 解释器。
- 不记录 API Key、请求正文或其他私密配置。

## 故障处理

- 无法创建辅助进程：接口返回 500，旧后台继续运行。
- 重启已安排但新实例未上线：前端在 45 秒后提示失败；用户可查看重启日志并手动运行 `启动服务.bat`。
- 重复点击或并发请求：首次请求生效，后续请求返回“重启已安排”，不再创建新的辅助进程。
- 活跃任务：确认框明确告知会中断；本功能不尝试迁移内存中的任务状态。

## 测试范围

- 空白画布右键菜单在本机显示重启项，节点右键菜单不显示。
- 局域网主机名访问时菜单不显示。
- 本机请求重启接口成功，非回环请求被拒绝。
- 重复请求不会安排多个重启。
- 重启后实例 ID 发生变化，前端自动刷新。
- 辅助进程创建失败时旧服务保持在线并返回清晰错误。
- 现有节点创建、连线、画布拖拽和右键菜单行为不受影响。
