# 动作提取节点连接 LLM 视频输入设计

## 目标

让无限画布中的“动作提取”节点可以直接连接 LLM 节点，并让深度白模（DEPTH）与骨骼姿态（POSE）输出在 LLM 输入链路中表现得与普通视频节点完全一致。

## 用户行为

- DEPTH 和 POSE 端口均可单独连接到 LLM。
- 两个端口可以同时连接同一个 LLM。
- LLM 按连接顺序接收全部有效视频，而不是只取最后一个。
- 仅连接一个端口时，只发送对应的视频。
- 未启用、未完成、失败或缺少 URL 的输出不会发送。
- LLM 节点的媒体提示需要显示已连接的视频数量。

## 数据流

1. 画布连接校验允许 `motionExtract -> llm`。
2. LLM 收集入站连接时保留每条连接的 `fromPort`。
3. 对动作提取节点调用统一的 `motionOutputVideoRefs(node, fromPort)`。
4. 有效结果转换为普通视频引用，包含：
   - `url`
   - `name`（`depth.mp4` 或 `pose.mp4`）
   - `kind: "video"`
   - 已有的视频元数据
5. LLM 请求继续通过现有 `/api/canvas-llm` 接口发送，动作提取结果进入 `videos` 数组，不进入 `images` 数组。

## 顺序与去重

- 以 `connections` 中的入站连接顺序为准。
- DEPTH 和 POSE 指向不同生成结果时都保留。
- 同一 URL 被重复连接时只发送一次，避免模型重复读取同一视频。
- 去重不改变首次出现的顺序。

## 错误处理

- 端口未指定时不猜测默认分支。
- 对禁用、未完成或失败的端口返回空引用，不污染 LLM 请求。
- 如果最终没有有效视频，LLM 仍可按现有纯文本/图片路径运行。
- 模型或供应商不支持视频时，沿用后端现有错误提示，不静默降级为图片。

## 兼容性

- 普通视频节点、Output 节点和素材组的视频输入行为保持不变。
- 不改变动作提取节点连接图片/视频生成节点及 Output 节点的既有行为。
- 不改变 LLM 文本和图片收集逻辑。
- 已保存画布无需迁移；旧连接结构缺少 `fromPort` 时不会错误发送某个动作分支。

## 测试

- `motionExtract -> llm` 连接校验通过。
- 仅连接 DEPTH 时，LLM 的 `videos` 只包含深度视频。
- 仅连接 POSE 时，LLM 的 `videos` 只包含姿态视频。
- 同时连接两个端口时，两个视频按连接顺序发送。
- 重复 URL 只发送一次。
- 禁用、未完成、失败和缺少 URL 的端口不发送。
- `/api/canvas-llm` 请求中视频位于 `videos`，不会进入 `images`。
- 现有普通视频输入测试继续通过。
